# 声纹库质量

打开 `meeting-asr web` 后进入 **库质量** `/quality`。这一页只回答一个问题:
**这个声纹库现在还能不能正确认出人,如果不能,下一步该修什么。**

## 为什么单独做一页

`voiceprint quality`(样本一致性)回答的是「一个人的样本彼此像不像」——
这是**簇内**问题。它对两种会让人**静默退出匹配**的故障完全失明:

- **当前模型下没有向量**:样本还在库里,但没有为当前 embedding model 生成
  向量。切 provider(例如换到 `local-campp`)后没重新 `voiceprint embed`
  就会这样。这个人不在匹配池里,但报告里**整行都不出现**。
- **样本全被隔离**:`quarantined` / `rejected` 之后没有样本参与匹配,
  一致性报告显示「0 suspicious」——因为已经没有样本可供挑错了。

两种情况在一致性视图里都是**绿色**,而人根本不会被匹配到。库质量页先回答
前置问题——**可用性**,再把它和阈值校准合成一条按严重度排序的待办队列。

## 三块内容

### 库体检卡

可用人数 / 匹配样本数 / 有效时长 / 严重问题数,加一条按可用性分层的健康条:

| 分层 | 含义 |
| --- | --- |
| 不可用 | 匹配样本 0 个,这个人永远不会被认出来 |
| 脆弱 | 1–2 个匹配样本,低于最小簇大小;质心刻画的是某次录音而非这个人 |
| 健康 | ≥3 个匹配样本 |

### 阈值卡

同人(genuine)与异人(impostor)两个分数分布叠画在同一条轴上。**中间那道空档
就是全部故事**:阈值落在空档里是安全的,落进同人分布里就在静默拒绝正确匹配。

游标可拖动,**每一格都本地实时定价**:这个阈值会误拒多少个正确匹配、误纳多少个
错误匹配。同时给出:

- **建议值**:取「最差异人分数 + 安全裕度」与「同人分数 5 分位」之间空档的中点,
  两侧都留余量。两个分布若已重叠,则退回等错误率(EER)点,并说明**此时改善样本
  质量比调阈值更有效**。
- **耦合副作用警告**:阈值降到 strong-margin 救援分(0.65)以下,那条「低于阈值
  但明显领先仍接受」的规则会变成死代码;降到 crosstalk 分数下限(0.5)以下,
  接受层能接受的说话人同时也符合串场标记条件。这两件事都不会报错,只会悄悄改变
  行为,所以在写入前显式提示。
- **样本量提示**:同人观测少于 30 个时,建议值只指方向,不是精确工作点。

应用会写入全局配置 `voiceprint.match_threshold`,影响之后所有匹配与重匹配
(包括 `project run` 的自动命名)。**「恢复默认」随时可退回内置值**,这是校准
判断失误时的退路。

### 待办队列

按严重度排序,**每条问题都挂一个动作**——不挂动作的指标只是好看的仪表盘。

| 问题 | 含义 | 动作 |
| --- | --- | --- |
| 当前模型下没有任何向量 | 完全不在匹配池 | 补齐嵌入 |
| 没有任何样本参与匹配 | 全被隔离/拒绝 | 查看样本 |
| 部分样本未嵌入 | 部分不参与匹配 | 补齐嵌入 |
| 只有 N 个匹配样本 | 低于最小簇大小 | 补采样本 |
| 只有 Ns 有效音频 | 决定稳定性的是总时长不是条数 | 补采样本 |
| 只来自一次录音 | 同时编码了房间/麦克风/状态,换场景会掉分 | 补采样本 |
| 阈值拒掉 X% 正确匹配 | 阈值高于同人分布 | 调整阈值 |
| 阈值接受 N 个错人分数 | 阈值低于异人分布 | 调整阈值 |

### 补采来源面板

「补采样本」以前只是 `navigate("/projects")`——把你送到问题的**起点**而不是答案:
你还得自己回忆这个人出现在哪几场会、逐个打开翻转写找名字。现在它在原地展开一个
按缺口排序的来源清单,每条给出:

| 列 | 含义 |
| --- | --- |
| 项目 + 说话人 | 去哪采、采谁 |
| 证据 | `已关联`(`speaker_person_map.json` 指向此人,强)/ `按名字`(`speaker_map.json` 显示名相同,弱) |
| 可用量 | 还剩多少条**够格当默认选项**的发言、合计多长(已入库的时间区间已扣除) |
| 理由 | 新的录音场次 / 上次采的样本被隔离了 / 素材充足 / 所剩无几 / 仅按名字匹配 / 这场已采过 |
| 候选 clip | 可试听、可勾选、**可直接采集**;默认按采集计划的推荐勾好 |

**采集就在面板里完成**:勾好点「采集 N 条」,进度、分数变化、历史回归、接受/回滚
全程不离开质量页。已经把 clip 挑出来摆在面前了,再跳一次页面重新挑,等于把刚算出
来的答案扔掉。

候选 clip **直接取自采集计划**(`plan_voiceprint_capture`),不是另选一套。两个原因:
一是它们带 `rel_path` —— 采集运行只认这个身份,自选的一套还得再 plan 一次才能采;
二是计划的推荐是**刻意跨时间轴散开**的,而按分数取前几条会挤在同一段独白里,刻画
出来的是某一种说话风格而不是一个人的声音。已入库的时间区间照旧扣除;若因此把默认
选中项滤没了,补足时按「离已选最远」而不是「分数最高」挑。

「完整挑选页」仍在,深链到 `/projects/<id>/capture?speaker=N`(采集页只显示那一位、
预选其推荐片段),留给本面板刻意不做的部分:音质分、进度条、以及那场会里的其他人。

**排序是缺口驱动的,不是「音质最好者胜」**:缺时长的人加权可用量,只有一场录音
的人加权新场次。否则算法会永远推荐那场已经采过的会——而同一场录音里再多采几条,
治不了「只有一场录音」,那需要这个人出现在**另一场**会里(面板会明说这一点)。

**隔离样本不计入匹配,所以「只产出过隔离样本」的项目仍算未采之地**,并额外标注
上次是被拒不是没采。实测中最优来源常常正是这种:某场会有十几分钟可用语音,而之前
从那儿采的几条全被隔离了——多半是质心太窄(只由另一场短会构成)而不是选错了人,
挑长句重采就能救回来。

局限:目前只认**已经命名过**的说话人。完全没命名过的项目里即使有这个人,也扫不
出来——那需要按声纹去比对未命名 track,是更贵的一条路。

## 对应的命令行

页面上的每件事都有等价 CLI:

```bash
# 库体检 + 待办队列(等价于页面上半部分,--json 供脚本/agent 消费)
meeting-asr voiceprint health

# 阈值校准证据(genuine/impostor 分布、EER、建议值)
meeting-asr voiceprint calibrate

# 读写阈值
meeting-asr config set voiceprint.match_threshold 0.60
meeting-asr config unset voiceprint.match_threshold

# 补齐当前模型缺失的向量
meeting-asr voiceprint embed

# 这个人还能去哪补采样本(等价于补采来源面板;可传姓名或 vpp id)
meeting-asr voiceprint sources <person>
meeting-asr voiceprint sources vpp-xxxxxxxxxxxxxxxx --json

# 样本一致性(簇内离群),与本页的可用性视角互补
meeting-asr voiceprint quality
```

## 切换 embedding provider 之后

**务必跑一次 `meeting-asr voiceprint embed`**,否则旧样本没有新模型的向量,
对应的人会静默退出匹配池。切换后阈值通常也要重新校准——不同模型的分数尺度不同,
为旧模型调的阈值放到新模型上可能系统性偏高或偏低。库质量页会把这两件事都作为
待办列出来。
